# Dify 工作流 → 统一智能体 导入与接线清单

目标：把 3 份 HR 工作流（考核报告 / 试卷阅卷 / 岗位百科出题）导入 Dify，发布成工具，再集合进一个「统一智能体」Agent；后端 `DIFY_AGENT_KEY` 配好后，悬浮球（公司 AI 助手）即可一句话触发全部能力。

本目录已备好修正版 DSL（已按本机 `company_agent` 库对齐：库名 `company_agent`、列 `employee_id`、密码 `964655`、连接参数改 `constant` 防 Agent 调工具时把 host 填成 localhost）：

- `进阶考核管理端_导入版.yml` —— 进阶考核报告（连库查 `assessment_stats`）
- `Test evaluation_导入版.yml` —— 试卷自动阅卷（连库查 `employees` + 上传 Word）
- `job_description and test_generation_导入版.yml` —— 岗位百科 + 智能出题（连知识库，不连库）

---

## 步骤 1：前置确认
- Dify 已启动且本机可访问（默认 http://localhost，API 在 /v1；若 Dify 跑在 Docker，宿主机 MySQL 用 `host.docker.internal` 连通，已在本包写死）。
- `company_agent` 库存在、表齐全（6 张业务表 + 2 张工资表），MySQL root 密码 `964655`。
- 已安装插件：`junjiem/db_query`（连库用）、`bowenliang123/md_exporter`（Markdown→Word 用，仅 job_description 需要）。

## 步骤 2：导入 3 份工作流
1. Dify 控制台 → **工作室** → **创建应用** → **导入 DSL**（或「导入 YAML」）。
2. 依次选择本目录 3 个 `_导入版.yml` 文件，各创建一个**工作流（Workflow）**应用。
3. 导入后逐个**预览运行**一遍，确认连库/连知识库节点不报红。

## 步骤 3：建岗位知识库（仅 job_description 需要）
- **知识库** → 创建 → 上传物流岗位文档（岗位说明/胜任力/培养路径等）。
- 记下该知识库 `dataset_id`，在 `job_description and test_generation_导入版.yml` 的「知识检索」节点里把 `dataset_ids` 填成它（若导入时已带旧 id，需替换为新库的 id）。

## 步骤 4：把工作流发布为「工具」
- 进入每个工作流应用 → **发布** → 右上角「作为工具发布」（Publish as Tool）。
- 发布后在「工具」列表能看到这 3 个工具，记下名称（建议改成好懂的：考核报告 / 试卷阅卷 / 岗位出题）。

## 步骤 5：建统一智能体 Agent 并挂工具
1. **创建应用** → 选 **Agent**（对话型）。
2. 在 Agent 的「工具」里 **添加** 步骤 4 发布的 3 个工具。
3. 写一段 Agent 提示词，明确路由规则（示例）：
   ```
   你是公司管理智能体。根据用户意图选择工具：
   - 涉及“考核报告/调岗/升职/胜任”→ 调用【考核报告】工具（传入工号）
   - 涉及“阅卷/批改试卷/打分”→ 调用【试卷阅卷】工具（传入工号与试卷文件）
   - 涉及“岗位说明/岗位测试/出试卷”→ 调用【岗位出题】工具（传入岗位名）
   - 考勤/报销/工资等常规问题→直接回答或调用对应本地能力
   不要臆造数据；查库时以工号(employee_id)为准。
   ```
4. **发布** Agent。

## 步骤 6：拿到 API Key 填进后端
1. 进入 Agent 应用 → **API 访问** → 生成 **API Key**。
2. 打开 `backend/.env`（没有就复制 `.env.example`），写入：
   ```
   DIFY_BASE_URL=http://localhost/v1
   DIFY_AGENT_KEY=上面生成的Key
   ```
3. 重启后端（`backend/start.bat` 或 uvicorn）。
4. 验证：前端点「智能助手」或悬浮球，发“生成 220401 的考核报告”，应返回分析报告（不再是“尚未接入”）。

## 步骤 7：前端对应功能（下一轮实现，本轮回滚未做）
- 悬浮球改名「公司 AI 助手」，加 4 个功能 chip：生成考核报告 / 出岗位试卷 / 阅试卷·上传 / 自由问答。
- 阅试卷 chip 打开文件框（上传 Word + 工号），后端新增 `POST /api/assessment/grade`（先 `/files/upload` 拿 file_id，再 `/workflows/run` 调阅卷工作流）。
- 报告/出题/自由问答走现有 `/api/chat`（已接统一智能体）。

## 常见坑
- **Agent 调工具报 Access denied / Connection refused**：连接参数被改成了 `constant` 即已规避（LLM 不会再把 host 填成 localhost）。若仍报，检查 Dify 容器内能否 `ping host.docker.internal`、MySQL 是否允许 root 远程/指定 host 登录。
- **报告/阅卷查不到数据**：确认库名是 `company_agent`、列是 `employee_id`（本包已修）。
- **job_description 跑出空**：知识库没建或 `dataset_ids` 没替换成新库 id。
- **忘记发布为工具**：Agent 里看不到工具，多半是工作流没走「作为工具发布」这一步。
